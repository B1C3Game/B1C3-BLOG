Whats a slug?

In this context, a slug is the URL-friendly identifier used to represent a piece of content.

For example, if you have a gallery page:

https://example.com/gallery/time-traveling-liver-eating-brute

then:

time-traveling-liver-eating-brute

is the slug.

A slug is typically:

lowercase
uses hyphens instead of spaces
unique within a collection
stable over time

Examples:

Title	Slug
Time Traveling Liver-Eating Brute	time-traveling-liver-eating-brute
Evil Witch Grind	evil-witch-grind
The First Mover	the-first-mover

What Copilot is complaining about is that some of your gallery entries apparently have slugs like:

7f4b5b2e-3d9c-4c44-8f1c-0e7f9b8e2d11

which is a UUID rather than a human-readable slug.

That's technically valid, but it's not great because:

URLs become ugly
harder to debug
worse for SEO
difficult to recognize content
registry files become unreadable

Instead of:

{
  "slug": "7f4b5b2e-3d9c-4c44-8f1c-0e7f9b8e2d11",
  "title": "Untitled"
}

you'd rather have:

{
  "slug": "time-traveling-liver-eating-brute",
  "title": "Time Traveling Liver-Eating Brute"
}

From Copilot's wording:

"UUID-based names and placeholder info"

it sounds like your variant registry contains entries whose folder names or IDs are UUIDs, and Copilot wants to inspect the actual image folders so it can replace them with meaningful metadata such as:

{
  "slug": "responsibility-exchange",
  "title": "Responsibility Exchange",
  "description": "Satirical editorial poster about responsibility as a luxury commodity."
}

rather than generic placeholders.

I think this is the problem with havning SPOCs and singular contact points. You are prefiltering. Assuming structure.

I think you're pointing at something deeper than prompt engineering.

What you're observing is that the image isn't generated from the prompt alone. It's generated from the prompt plus the frame that produced the prompt.

A few examples:

Direct conversation

You say:

Make a poster about responsibility.

The model has access to:

your wording
previous messages
tone
recurring themes
implicit priorities
what you've been reacting positively to

The prompt is actually much larger than the visible text.

Structured dataprompt

You write:

title: Responsibility
style: Editorial realism
tone: Serious
layout: Vertical 4:5

Now you've compressed reality into fields.

That's powerful because it's inspectable.

But you've also thrown away:

hesitation
emphasis
narrative context
emotional weighting
the reason you asked

The structure helps consistency but loses information.

Reverse-engineered prompt

This is the interesting one.

You take an image.

Then you reconstruct:

What prompt must have created this?

But you're not recovering the original prompt.

You're creating a new interpretation of the image.

The reverse-engineered prompt contains information from:

the image
your interpretation
what you notice
what you ignore

So the regenerated image drifts.

Not because the model failed.

Because you've changed the representation.

Why Copilot behaves differently in different directories

This is the part that caught my attention.

If Copilot is looking at:

/gallery/

it thinks:

These are website assets.

If it is looking at:

/prompts/

it thinks:

These are prompt definitions.

If it is looking at:

/nsfw-memes/

it thinks:

These are content collections.

Same files.

Different frame.

Different inferred ontology.

Different recommendations.

This is actually related to your SPOC observation.

A Single Point of Contact is often treated as:

Reality
    ↓
SPOC
    ↓
Organization

But the SPOC isn't just forwarding information.

The SPOC is:

compressing
filtering
categorizing
translating
interpreting

So the organization never sees reality.

It sees the SPOC's model of reality.

Sometimes that's necessary.

Sometimes that's where failures begin.

One way to phrase the insight is:

Structure is not neutral.

Every structure preserves some information and destroys other information.

A slug preserves identity but destroys narrative.

A registry preserves organization but destroys context.

A prompt template preserves repeatability but destroys spontaneity.

A SPOC preserves coordination but destroys perspective diversity.

None of those are automatically bad.

The question becomes:

What information did this structure make expensive to see?

That's often where the interesting stuff is hiding.
